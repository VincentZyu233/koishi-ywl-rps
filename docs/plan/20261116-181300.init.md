## 一、 为什么将 `koishi-ywl-rps` 打造为整合包？

在上一阶段，我们已经在 `rpsluna` 中实现了全套核心插件（调度器、马尔可夫博弈、经典 Iocaine 策略、NewAPI 心理战大模型、窗口捕获网关、独立 Web 对战 Portal）。

如果仅提供插件代码，使用者需要自行下载 Koishi、新建项目、配工作区、在 `koishi.yml` 里手工写几十行配置，门槛极高且容易踩坑。
而**整合包（Bundle）** 的理念是：**“交付整车，而不是零配件”**。使用者只需执行两行命令：
```bash
yarn
yarn dev
```
即可直接唤醒包含所有预置策略、独立 Web 竞技场与后台监控的大型交互应用。

## 三、 开箱即用配置系统设计 (`.env` + `.env.local` + `koishi.yml`)

### 1. 配置文件三层架构
1. **`.env` (公开示范配置，提交至 Git)**：
   - 提供所有可配置项的**安全占位符**与**官方默认推荐值**；
   - 即使使用者不配置任何私有 Key，也能使用真随机、马尔可夫、Iocaine 策略和独立 Web 界面完整体验，不会抛红崩溃。
2. **`.env.local` (本地私密覆盖，被 `.gitignore` 严密忽略)**：
   - 开发者或使用者填写真实的 NewAPI / OpenAI Key、私有端口或反向代理域名；
   - 优先级高于 `.env`，修改后无需改动 `koishi.yml`。
3. **`koishi.yml` (基于环境变量插值的全量装配模板)**：
   - 使用 Koishi 原生支持的 `${{ env.VARIABLE_NAME }}` 语法；
   - 声明预装的所有核心模块与合理默认开关。

---

### 2. 拟定环境变量模板规范

#### ① `.env` (示范文件，可直接提交)
```ini
# ==========================================
# 🎮 rpsluna 整合包基础配置 (示范公开值)
# ==========================================

# 1. 独立公网 Portal 对战大屏端口 (供 FRP 穿透或局域网访问)
RPS_PORTAL_PORT=18080

# 2. 外部视觉推流接收端口 (用于接收 Python window_detector 推流)
RPS_VISION_PORT=18082

# 3. 大模型心理战策略配置 (示范占位符，不含真实密码)
LLM_ENDPOINT=https://api.openai.com/v1
LLM_API_KEY=sk-demo-placeholder-please-replace-in-env-local
LLM_MODEL=gpt-4o-mini
LLM_PERSONA=toxic
```

#### ② `.env.local` (使用者本地私有填报，永不入库)
```ini
# 本地私密配置覆盖示例
LLM_ENDPOINT=https://your-newapi-proxy.com/v1
LLM_API_KEY=sk-real-secret-key-abcdef123456
```

#### ③ `koishi.yml` (装配示范)
```yaml
plugins:
  # 基础框架支撑
  server:
    port: 5140
  console: {}

  # rpsluna 核心服务
  rpsluna-core:
    defaultRoomName: 赛博博弈竞技场
    enableCommand: true

  # 纯按键与兜底输入
  rpsluna-adapter-buttons:
    autoRegister: true

  # 窗口视觉推流网关
  rpsluna-adapter-window:
    port: ${{ env.RPS_VISION_PORT }}

  # 博弈算法全家桶 (马尔可夫 + 经典博弈大师)
  rpsluna-strategy-markov:
    order: 2
    decayFactor: 0.85

  rpsluna-strategy-all:
    enableIocaine: true
    enableCheat: true

  # 大模型读心术 (读取环境变量)
  rpsluna-strategy-llm:
    endpoint: ${{ env.LLM_ENDPOINT }}
    apiKey: ${{ env.LLM_API_KEY }}
    model: ${{ env.LLM_MODEL }}
    persona: ${{ env.LLM_PERSONA }}

  # 独立 Web Portal (供 FRP 穿透公网)
  rpsluna-renderer-portal:
    port: ${{ env.RPS_PORTAL_PORT }}
    title: rpsluna 赛博竞技场

  # 控制台监控扩展
  rpsluna-renderer-console:
    broadcastEvents: true
```

## 四、 整合包目录结构与打包规范

作为整合包分发时，有两种发布形态：

### 形态 A：内嵌子工作区（单仓库整合包，最推荐分发给评审）
将 `rpsluna` 模块直接作为 `koishi-ywl-rps/packages/` 的一部分，整合为一个单一仓库：
```
koishi-bundle-rpsluna/
├── .env                         # 公开示范配置
├── .env.local                   # 本地真实配置 (gitignore)
├── koishi.yml                   # 全局装配插值配置
├── package.json                 # 根整合包配置
├── packages/                    # 内置全部 rpsluna 套件源码
│   ├── core/
│   ├── adapter-window/
│   ├── adapter-buttons/
│   ├── strategy-markov/
│   ├── strategy-all/
│   ├── strategy-llm/
│   ├── renderer-portal/
│   └── renderer-console/
├── tools/
│   └── window_detector/         # Python UV 视觉伴侣脚本
└── README.md                    # 开箱即用完整说明书
```

### 形态 B：组合式（当前开发模式）
`koishi-ywl-rps` 通过 `external/` 或 `workspaces` 链接外部的 `rpsluna` 仓库。
